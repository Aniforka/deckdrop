# DeckDrop

«DeckDrop», помощник Steam и галерея для Steam Deck по локальной сети. Открываешь
страницу с телефона или ПК, вставляешь ссылку или кидаешь файл, и дек сам качает его на
внутренний диск или microSD. Ссылки Mega он расшифровывает сам. Архивы распаковывает,
а если архив закрыт, спросит пароль. Игру добавляет в Steam под нормальным именем, ставит
Proton по умолчанию и рисует все виды обложек: с VNDB для новелл или из иконки exe.
Отдельные вкладки: скачанные архивы и защищённая паролем галерея скриншотов и записей.
Сейвы можно забрать в zip и вернуть обратно, патчи — положить прямо в папку игры.

Ставится одним файлом на Python, только стандартная библиотека. На стоковом SteamOS
ничего доустанавливать не нужно, и обновления системы его не ломают.

*A LAN inbox and Steam helper for Steam Deck: paste a link or drop a file from your phone,
the Deck downloads, unpacks and adds the game to Steam with cover art. The UI is in Russian.*

## Установка и запуск

### Что нужно

- Steam Deck на SteamOS 3.x. На обычном Linux со Steam тоже работает, если есть
  `python3` 3.8+ и `systemd --user`.
- Дек и телефон (или ПК) в одной Wi-Fi-сети.
- Интернет на деке для установки с GitHub. Без него можно поставить с ПК, см. ниже.
- По желанию: `ffmpeg` (точная подгонка обложек, склейка записей Steam со звуком)
  и `7z` или `bsdtar` (архивы 7z и rar). Всё это необязательно: без них zip распаковывается
  встроенными средствами, а обложки ставятся как есть.

Root-пароль, `sudo`, выключение read-only и Decky Loader **не нужны**: DeckDrop живёт
в домашней папке и запускается как пользовательский сервис.

### Установка с GitHub

1. Переключи дек в Desktop Mode: кнопка Steam → «Питание» → «Переключиться на рабочий стол».
2. Открой **Konsole** (меню приложений → «Система» → Konsole).
3. Скачай установщик. Команда одной строкой:

   ```bash
   wget https://github.com/Aniforka/deckdrop/releases/latest/download/install.sh
   ```

4. Запусти его:

   ```bash
   sh install.sh
   ```

   Установщик положит `deckdrop.py` в `~/deckdrop`, проверит, что файл скачался целиком,
   зарегистрирует пользовательский сервис `deckdrop` с автозапуском и сразу его запустит.
   В конце он напечатает **адрес страницы** и **PIN администратора**, запиши их.

5. Можно возвращаться в Gaming Mode: сервис работает и там, и после перезагрузки.

Без установщика то же самое делается вручную:

```bash
mkdir -p ~/deckdrop
```

```bash
wget -O ~/deckdrop/deckdrop.py https://github.com/Aniforka/deckdrop/releases/latest/download/deckdrop.py
```

```bash
python3 ~/deckdrop/deckdrop.py --install
```

Буква в ключе `-O` — заглавная латинская **O**, не ноль.

### Установка с ПК по локальной сети

Подходит, если у дека нет выхода на GitHub или хочется поставить свою правленую копию.

1. На ПК скачай `deckdrop.py` и `install.sh` со страницы
   [последнего релиза](https://github.com/Aniforka/deckdrop/releases/latest) (или собери
   свою копию, см. [Разработка](#разработка)), открой терминал в этой папке и запусти
   раздачу. Окно не закрывай:

   ```bash
   python -m http.server 8000
   ```

2. Узнай адрес ПК в локальной сети: на Windows команда `ipconfig`, строка «IPv4-адрес»;
   на Linux и macOS — `ip addr` или `ifconfig`. Дальше в примерах `192.168.1.10`.
3. На деке в Konsole (Desktop Mode):

   ```bash
   wget 192.168.1.10:8000/install.sh
   ```

   ```bash
   sh install.sh http://192.168.1.10:8000/deckdrop.py
   ```

4. Когда установщик напишет адрес и PIN, раздачу на ПК можно закрыть через Ctrl+C.

Если на ПК включён брандмауэр, при первом запуске `python` он спросит, пускать ли
подключения из частной сети — разреши.

### Первый запуск: адрес и PIN

Страница открывается с любого устройства в той же сети:

- **`http://steamdeck.local:8088`**, где `steamdeck` — имя дека. Его видно в выводе
  установщика и в «Настройки» → «Система» → «Имя хоста». Адрес `.local` понимают iOS,
  macOS, Linux и Windows 10+; некоторые Android-браузеры его не находят.
- **`http://<IP дека>:8088`** — работает везде. IP напечатан установщиком и виден
  на вкладке «Настройки» самой страницы.

Сохрани адрес в закладки или добавь на домашний экран телефона.

**PIN администратора** нужен для опасных действий: удаление, обновление, смена прокси.
При первой установке DeckDrop придумывает случайный PIN из 4 цифр и печатает его.
Поменять его можно на вкладке «Настройки». Если PIN потерялся, посмотри его на деке:

```bash
grep admin_pin ~/.config/deckdrop/state.json
```

Порт 8088 выбран не случайно: 8080 занимает отладочный порт самого Steam, через который
DeckDrop управляет клиентом (см. [Управление Steam](#управление-steam)).

### Обновление

Внизу страницы есть кнопка **«Обновить утилиту»**. По умолчанию она берёт `deckdrop.py`
из последнего [релиза](https://github.com/Aniforka/deckdrop/releases/latest). Можно указать
и свою ссылку, например раздачу с ПК
`http://192.168.1.10:8000/deckdrop.py`: адрес запоминается. DeckDrop скачает файл, проверит
его и перезапустится сам. Если в новой версии сменился порт, страница сама переедет
на новый адрес. Настройки, пароли и список игр при обновлении сохраняются.

Повторный запуск `sh install.sh` тоже обновляет до последней версии.

Версии 0.3.23 и старше обновлялись из ветки `main`; начиная с 0.3.24 сохранённый адрес
сам переключается на релизы, делать ничего не нужно.

### Удаление, логи, ручной запуск

| Что | Команда на деке |
|---|---|
| Логи в реальном времени | `journalctl --user -u deckdrop -f` |
| Перезапустить | `systemctl --user restart deckdrop` |
| Остановить до перезагрузки | `systemctl --user stop deckdrop` |
| Удалить сервис | `python3 ~/deckdrop/deckdrop.py --uninstall` |
| Запустить без сервиса, в терминале | `python3 ~/deckdrop/deckdrop.py` |

`--uninstall` убирает только сервис. Скачанные игры, `~/deckdrop`, настройки
(`~/.config/deckdrop`) и кеш (`~/.cache/deckdrop`) остаются; их можно удалить руками.
Маркер управления Steam удаляется выключением этой функции в настройках до удаления.

### Настройка через переменные окружения

Переменные задаются в `~/.config/systemd/user/deckdrop.service`, в секции `[Service]`
строками вида `Environment=DECKDROP_PORT=8090`. После правки:
`systemctl --user daemon-reload`, затем `systemctl --user restart deckdrop`.

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `DECKDROP_PORT` | `8088` | порт страницы |
| `DECKDROP_GAMES` | `~/Games` | папка игр на внутреннем диске |
| `DECKDROP_DISKS` | — | дополнительные диски: `метка=/путь;метка2=/путь2` |
| `DECKDROP_STEAM` | ищется сам | корень Steam, если он не в стандартном месте |
| `DECKDROP_STATE` | `~/.config/deckdrop/state.json` | файл настроек и состояния |
| `DECKDROP_CEF` | `1` | `0` — не включать управление Steam |
| `DECKDROP_CEF_PORT` | `8080` | отладочный порт Steam |
| `DECKDROP_PIN` | случайный | начальный PIN при первой установке |
| `DECKDROP_UPDATE_URL` | этот репозиторий | адрес обновления по умолчанию |
| `DECKDROP_EXTRACT` | `1` | `0` — не распаковывать архивы |
| `DECKDROP_KEEP` | `1` | `0` — удалять архив после успешной распаковки |

## Управление Steam

Steam держит настройки в памяти и переписывает файлы при выходе, поэтому правки `config.vdf`
и `shortcuts.vdf` при запущенном клиенте пропадают. DeckDrop идёт тем же путём, что Decky
Loader: включает у Steam локальный отладочный порт CEF (файл-маркер
`.cef-enable-remote-debugging` в папке Steam) и через него просит клиент добавить ярлык
с нужным именем, выбрать Proton, поставить обложки, убрать ярлык.

- Порт открывается только на самом деке (localhost), снаружи он недоступен.
- Включается после **одной перезагрузки дека**. Состояние видно внизу страницы и в настройках.
- Пока управления нет, игры добавляются старым способом через `steamos-add-to-steam`, а имя
  и Proton встают в очередь и применяются автоматически, как только управление появится.
- Выключается в настройках, тогда маркер удаляется и Steam при следующем запуске порт закроет.

## Пароли

- **PIN администратора**: удаление игры, удаление медиа, сброс пароля галереи, прокси,
  обновление утилиты. Случайный при установке, меняется на вкладке «Настройки», от 4 до 8 цифр.
- **Пароль галереи**: задаётся при первом заходе на вкладку «Медиа», спрашивается при каждом
  открытии вкладки, хранится хешем PBKDF2. Сессия живёт 12 часов. Сброс по PIN внизу страницы.

## Вкладка «Игры»

- Ссылка в поле, Ctrl+V на странице, или перетаскивание файла и ссылки. Рядом с заголовком
  выбор диска: внутренний или microSD, с остатком места. Выбор запоминается.
- Архивы (zip, 7z, rar, tar.\*) распаковываются в `<диск>/Games/<имя архива>`; хвост `(1)`
  от повторного скачивания на ПК из имени папки убирается. Зашифрованный архив останавливается
  со статусом «нужен пароль», поле ввода прямо в задании, галочка «запомнить» добавляет пароль
  в список, который потом пробуется автоматически.
- В списке каждая игра — компактная карточка: имя, диск, добавлена ли в Steam, есть ли обложки.
  Игры, добавленные вручную кнопкой «+ своя игра», помечены «своя».
  Нажатие открывает **страницу игры**; кнопка «← к списку» или системная «назад» на телефоне
  возвращает обратно.

**Остановка.** У каждого скачивания, в том числе ждущего «в очереди», есть кнопка «отмена»:
задание из очереди останавливается сразу, текущее — за секунду, недокачанное удаляется.
Кнопка «остановить всё» в заголовке заданий снимает всю очередь разом, а «очистить» убирает
завершённые, ошибочные и отменённые задания из списка.

## Своя игра (импорт)

Кнопка «+ своя игра» в заголовке списка добавляет **одну игру**, которая уже лежит где-то
на деке, например установленную раньше вручную. Достаточно указать путь к файлу запуска:

    /home/deck/Games/MyGame/Game.exe

DeckDrop ничего не копирует, не перемещает и не устанавливает: папка остаётся на месте
и просто появляется в списке отдельной карточкой с пометкой «своя». Дальше она ведёт себя
как любая другая: имя, Proton, обложки, сейвы, добавление в Steam, скрытие — всё меняется так же.

**Что переносится при импорте.** Если игра уже есть в ярлыках Steam, DeckDrop прочитает
и запишет себе её текущие настройки: имя из `shortcuts.vdf`, версию Proton из `config.vdf`
и обложки из папки `grid`. Записывается только собственный файл состояния DeckDrop;
сам Steam, его файлы и файлы игры при импорте не меняются вообще. Дальше эти значения
можно править как у любой другой игры.

Если игры в Steam ещё нет, импорт не назначает ни имени, ни Proton, ни обложек: показывается
только то, что видно из файлов, а в Steam она попадёт лишь по кнопке «в Steam».

- Это одна игра, а не корневая папка со списком игр: содержимое не сканируется на подыгры.
  Чтобы показать несколько игр, добавь каждую отдельно.
- Можно указать и саму папку игры. Если exe лежит в подпапке вроде `bin` или `game`,
  берётся папка уровнем выше.
- В окне импорта отдельным списком показаны игры, которые **уже есть в ярлыках Steam**,
  но лежат вне папок DeckDrop: их можно добавить одним нажатием.
- Добавлять можно из домашней папки и с подключённых носителей.
- «Убрать из DeckDrop» на странице игры убирает карточку и ничего не удаляет с диска.
  Кнопка «удалить с дека 🔒» рядом работает как обычно, по PIN, и удаляет файлы по-настоящему.

## Страница игры

- **Запуск**: все исполняемые файлы игры. Рекомендуется Linux-сборка (`.sh`, `.x86_64`),
  если она есть: идёт нативно, без Proton; настройка «Предпочитать Linux-сборку» это меняет.
  У добавленного файла галочка и выбор Proton прямо в строке.
- **В Steam**: имя берётся из имени исполняемого файла, без расширения, с большой буквы
  (`yosuga.exe` → «Yosuga»); для безликих `game.exe`, `start.exe` и подобных — из имени папки.
  Версии `v1.4`, теги в скобках и `(1)` отбрасываются. Если вариантов несколько (файл, папка,
  другие файлы игры), откроется окно с готовыми вариантами, полем для своего имени и выбором
  Proton для этой игры. Имя потом меняется карандашом рядом с заголовком.
- **Обложки**: все пять слотов Steam с предпросмотром текущих картинок. У каждого слота
  «заменить…» (своя картинка с телефона или ПК, PNG или JPEG) и «VNDB…» (обложка или любой
  скриншот выбранной новеллы именно в этот слот). У слота «Иконка» есть третья кнопка
  «из exe»: она берёт иконку прямо из исполняемого файла и ставит только в этот слот.
  Кнопки над сеткой заполняют все слоты сразу: с VNDB или из иконки exe.
- **Сейвы**: что войдёт в бэкап, «скачать бэкап» и «импортировать zip».
- **Действия**: скрыть из списка, удалить с дека по PIN (галочка убирает и ярлык из Steam).
- **Сведения**: папка, размер, имя в Steam, AppID, Proton, источник обложек и заметки VNDB.

### Файлы игры (патчи)

На странице любой игры есть карточка «Файлы игры»: туда можно загрузить патч или любой другой
файл прямо в папку игры, с телефона или ПК. Путь пишется **относительно папки с exe**:

| Путь | Куда ляжет |
|---|---|
| пусто | рядом с exe (по умолчанию) |
| `data/patch` | в подпапку рядом с exe, её создаст, если нет |
| `../` | на уровень выше exe, например если он лежит в `bin/` |

Выйти за пределы папки игры нельзя. Если у игры несколько exe, можно выбрать, от какого
считать. Под полем видно, куда именно ляжет файл и что уже лежит в этой папке. Можно выбрать
сразу несколько файлов. Если файл с таким именем уже есть, DeckDrop спросит, а самый первый
вариант сохранит рядом как `имя.bak`: при повторных обновлениях патча оригинал не потеряется.

**Распаковать архив.** Если патч пришёл архивом, который надо «открыть и заменить», нажми
«распаковать архив…» в той же карточке. Архив сначала распакуется на деке в сторонку, и
DeckDrop покажет, что в нём лежит, куда ляжет, сколько файлов добавит и сколько заменит
(с примерами). Если всё содержимое архива завёрнуто в одну папку (`Patch v2/…`), можно
снять её галочкой, чтобы файлы легли прямо в выбранную папку. Если внутри `BepInEx/…` или
`data/…`, галочку не ставь: эта папка и есть часть патча. Заменяемые файлы по умолчанию
сохраняются как `.bak` по тому же правилу: только самый первый вариант. Архивы с паролем
спросят пароль, сохранённые пароли из настроек пробуются сами. Подходят zip, 7z, rar и tar.
Если не подтвердить распаковку, ничего не изменится, а распакованное в сторонку удалится.

## Обложки

Слоты Steam: вертикальная капсула 600×900 (её видно в Big Picture), широкая 920×430,
hero-баннер 1920×620, логотип и иконка. Автоматически после добавления ставится полный набор.

- **VNDB** (экспериментально): по имени игры ищется новелла в базе VNDB. Официальная обложка
  идёт в вертикальный слот, один из скриншотов кадрируется в широкий слот и в hero, логотип
  рисуется текстом с названием, иконка берётся из exe. Автопоиск включается в настройках
  и срабатывает только при уверенном совпадении названия. Картинки 18+ ставятся как есть;
  в настройках есть галочка «Пропускать 18+», если понадобится.
- **Из иконки exe**: свой разбор PE-ресурсов, иконка на подложке цвета самой иконки.
  Работает без внешних библиотек.
- **Свои картинки**: любой слот можно заменить файлом с устройства или выбранной картинкой
  с VNDB.
- Файлы всегда пишутся в `userdata/<id>/config/grid/`; если управление Steam активно, картинки
  дополнительно отправляются в запущенный клиент и видны сразу, иначе — после перезапуска Steam.
  Что реально лежит в слотах, видно на странице игры.
- С `ffmpeg` картинки кадрируются точно под слоты, а логотип рисуется текстом. Без него
  VNDB-картинки ставятся как есть, логотип пропускается.

## Вкладка «Архивы»

Всё, что лежит в `_inbox` на всех дисках: размер, дата, распакован ли. Нераспакованный можно
распаковать отсюда, любой удалить. «Удалить распакованные» чистит одним нажатием только те,
для которых уже есть папка игры.

«Очистить всё» удаляет из `_inbox` вообще всё: архивы, распакованные и нет, отдельные
файлы и остатки недокачанного. Перед удалением покажет, сколько штук и гигабайт уйдёт.
Папки игр не трогаются, как и то, что качается или распаковывается прямо сейчас.

## Вкладка «Медиа»

Скриншоты Steam с названиями игр, записи Steam (склеиваются из фрагментов в mp4, со звуком
при наличии `ffmpeg`), всё видео и картинки из `~/Videos` и `~/Pictures`. Тап по плитке
открывает просмотр: «скачать» сохраняет на телефон, «удалить с дека 🔒» освобождает место
по PIN. Видео отдаётся с Range-запросами, поэтому нормально играет и перематывается на iOS.

## Сейвы

В карточке игры «бэкап / импорт». DeckDrop собирает в zip папки сохранений внутри игры
(`save`, `saves`, `savedata` и похожие), пользовательские папки из префикса Proton
(`AppData`, `Documents`, `Saved Games` без системного мусора) и для Linux-сборок каталоги
Ren'Py и Unity в домашней папке. Перед импортом автоматически делается копия текущих
сохранений в `~/.cache/deckdrop`. Импорт не даёт файлам вылезти за пределы целевых папок.

## Какие ссылки работают

| Источник | Что происходит |
|---|---|
| Прямая ссылка на файл | скачивается как есть |
| Яндекс.Диск (`disk.yandex.*`, `yadi.sk`) | прямая ссылка берётся через публичный API Диска |
| Google Drive | через `drive.usercontent.google.com` с `confirm=t` |
| Mega (`mega.nz`, `mega.co.nz`) | файл и папка, новые и старые ссылки; расшифровывается на деке |
| Telegram | ссылки не существует: скачать на телефоне и загрузить файл |
| Страница с кнопкой (itch.io, обменники с таймером) | сервер видит HTML вместо файла и пишет об этом |

## Mega

Mega шифрует файл прямо в браузере того, кто его выкладывал, и на сервере лежит уже
зашифрованное. Ключ хранится в самой ссылке, в части после решётки, — поэтому **копировать
надо ссылку целиком**. Без хвоста после `#` расшифровать нечем, и DeckDrop сразу об этом скажет.

Работают все виды ссылок:

| Ссылка | Что будет |
|---|---|
| `mega.nz/file/<код>#<ключ>` | скачается сразу, имя файла берётся из зашифрованных данных |
| `mega.nz/folder/<код>#<ключ>` | откроется список файлов с размерами; отмеченное скачается одной игрой |
| `mega.nz/folder/<код>#<ключ>/file/<код>` | скачается только этот файл |
| Старые `mega.nz/#!<код>!<ключ>` и `#F!<код>!<ключ>` | тоже понимаются |
| `mega.nz/#P!…` (под паролем) | не умеет: открой в браузере и возьми обычную ссылку |

Как это работает: DeckDrop спрашивает у Mega адрес для скачивания, тянет файл кусками,
расшифровывает их на лету (AES-CTR через системную libcrypto, ту же, что использует сам
SteamOS) и складывает уже нормальный файл — распаковка и добавление в Steam дальше идут
как обычно. В конце сходится контрольная сумма Mega: если файл побился по дороге,
DeckDrop не выдаст его за целый (проверку можно выключить в настройках).

Если связь оборвётся посреди многогигабайтного архива, закачка продолжится с того же места,
а не начнётся заново. Файлы качаются по одному: Mega ругается на несколько соединений с
одного адреса.

**Папка с Mega — это одна игра.** Если отметить в списке несколько файлов, получится одно
задание с общим прогрессом («Игра · файл 12 из 300»). Файлы собираются во временной папке
с сохранением всей структуры (`BepInEx/plugins/...`, `Game_Data/Managed/...`, пустые папки
тоже), а в конце папка целиком становится игрой в `~/Games/<имя папки>` и появляется в списке.
Если в папке только архивы (плюс readme), они ложатся во «входящие», и распаковывается
главный: обычный архив, `.part1.rar` или `.7z.001`; остальные части помечаются
«часть архива». Один отмеченный файл идёт во «входящие», как обычная ссылка.

Если Mega пишет про лимит трафика — это её ограничение на бесплатные ссылки,
помогает подождать несколько часов или включить прокси.

## Сеть и прокси

Провайдер может рвать соединение с VNDB: в сведениях игры тогда видно
`соединение сброшено (Errno 104)`. На этот случай в настройках есть прокси,
которым пользуется **только сам DeckDrop**. Остальной дек ходит в интернет как обычно,
ничего системного не меняется.

- Поддерживаются `socks5://хост:порт` и `http://хост:порт`, можно с логином:
  `socks5://логин:пароль@хост:порт`. Клиент SOCKS5 написан на стандартной библиотеке,
  имена хостов резолвятся на стороне прокси.
- **VLESS напрямую не поддерживается** и не может: это транспорт Xray с TLS/Reality.
  Но он и не нужен: VLESS говорит клиент Xray, а наружу отдаёт локальный вход SOCKS5.
  Цепочка получается DeckDrop → SOCKS5 → Xray → VLESS → сервер.
- Два способа: указать адрес домашнего ПК, если на нём уже крутится клиент с входом SOCKS5
  (например `socks5://192.168.1.10:10808`, в клиенте надо разрешить подключения из локальной
  сети), либо положить клиент Xray на сам дек и указать `socks5://127.0.0.1:10808`.
- Галочка «через прокси качать и сами игры» распространяет прокси на загрузки файлов.
  По умолчанию выключена: прокси нужен для VNDB, а большие файлы быстрее качать напрямую.
- Кнопка «Проверить связь с VNDB» показывает, доступны ли `api.vndb.org` и `t.vndb.org`
  напрямую и через прокси, с временем ответа.
- Адрес прокси может содержать логин и пароль, поэтому он **закрыт PIN**: на странице виден
  только замаскированный вид `socks5://***:***@хост:порт`, настоящее значение не уходит
  в браузер без PIN. Запросы к VNDB повторяются трижды с паузой: обрывы часто разовые.

## Вкладка «Настройки»

Открывается вкладкой или шестерёнкой ⚙ в шапке. Каждый переключатель сохраняется сразу.
Proton по умолчанию для всех новых игр (список найденных Proton и GE-Proton; у каждой
уже добавленной игры своя версия выбирается отдельно на её странице), прокси и проверка связи,
предпочитать Linux-сборку, автопоиск VNDB и пропуск 18+, управление Steam, проверка
контрольной суммы Mega, пароли архивов, адрес обновления, смена PIN, сведения о дисках и адресах.

На телефоне верхняя панель с вкладками уезжает при прокрутке вниз и возвращается
при прокрутке вверх, чтобы не занимать экран.

## Безопасность

DeckDrop рассчитан на **домашнюю сеть**. Галерея и опасные действия закрыты паролем
и PIN, но загрузка файлов и ссылок открыта: любой в твоей Wi-Fi-сети может положить файл
на дек. Не открывай порт 8088 в интернет и не запускай DeckDrop в общественных сетях.
Шифрования (HTTPS) нет, поэтому пароли по сети идут открытым текстом — ещё одна причина
держать его только дома.

## Разработка

Исходники лежат пакетом в [`src/deckdrop`](src/deckdrop), по модулю на область.
Пользователю по-прежнему достаётся один файл: [`tools/build.py`](tools/build.py) собирает
пакет в `dist/deckdrop.py`, и именно его выкладывают релизы. Внешних зависимостей нет,
ни у приложения, ни у сборки.

```
src/deckdrop/
  __init__.py        версия и описание
  app.py             точка входа: сервер и фоновые циклы
  config.py          переменные окружения, пути, константы, log()
  state.py           state.json, PIN, пароль галереи
  storage.py         диски, microSD, корни игр
  jobs.py            задачи загрузки/распаковки
  paths.py           имена файлов, тома архивов, размеры
  net.py             прокси (SOCKS5/HTTP), HTTP, повторы
  downloads.py       загрузка по ссылке, очередь, отмена
  aes.py, mega.py    Mega: AES (libcrypto или чистый Python), API, папки
  archives.py        распаковка, пароли, вкладка «Архивы»
  detect.py          exe в папке игры и человеческое имя игры
  steam/             файлы Steam (VDF), Proton, управление клиентом через CEF, ярлыки
  art/               PNG/ICO/PE-иконки, ffmpeg, обложки из иконки и VNDB
  games.py           вкладка «Игры», импорт, добавление в Steam
  saves.py, media.py, patches.py
  update.py          самообновление и перезапуск
  service.py         установка сервиса systemd
  bundle.py          откуда запущена копия: собранный файл или src/
  web/
    server.py        HTTP API
    page.py          сборка страницы из файлов ниже
    index.html, app.css, app.js
tools/
  build.py           сборка в один файл
  dev.py             запуск прямо из src/, без сборки
tests/
```

Модули зависят только «вниз»: `web/server` и `app` сверху, `config` и `state` внизу,
циклических импортов нет.

Запуск на ПК без сборки (правки HTML/CSS/JS и Python видны после перезапуска):

```bash
python tools/dev.py
```

На Windows и без Steam часть функций просто покажет «недоступно», а страница откроется
на `http://localhost:8088`. Чтобы не трогать свои папки, укажи отдельные
`DECKDROP_STATE` и `DECKDROP_GAMES`. Из исходников не работают только кнопка обновления
и `--install`: они нужны собранному файлу.

Собрать и проверить то же, что CI:

```bash
python tools/build.py                     # -> dist/deckdrop.py
python -m pyflakes src tools tests
python -m unittest discover -s tests      # модули, AES, PNG, VDF, обновление
python tests/smoke.py tools/dev.py        # сервер из исходников
python tests/smoke.py dist/deckdrop.py    # сервер из собранного файла
```

`tests/test_update.py` проверяет обновление целиком: установленная копия скачивает
новую сборку по HTTP и подменяет себя, а старая однофайловая 0.3.23 тоже её принимает.

`tests/test_user_data.py` — главный тест: обновление не должно терять и переписывать
данные пользователя. Для каждого из последних релизов (теги `v*`) он запускает старую
версию и через её же веб-интерфейс меняет PIN, все настройки (включая прокси с паролем),
задаёт пароль галереи, скрывает и импортирует игры; в `state.json` добавляются игры,
добавленные в Steam, отложенные операции и ключ от будущей версии. Потом нажимает
«Обновить» в старой версии, указав на новую сборку, и проверяет: не изменился ни один
файл, кроме самой программы; новая версия на тех же данных показывает те же настройки
и игры, принимает старый PIN и пароль галереи, а после записи `state.json` в нём
сохранено всё, что было. В CI это отдельный обязательный шаг, без него релиз не выходит.

**Выпуск версии.** Подними `__version__` в [`src/deckdrop/__init__.py`](src/deckdrop/__init__.py)
и влей в `main`. GitHub Actions ([`release.yml`](.github/workflows/release.yml)) соберёт файл,
прогонит проверки, создаст тег `vX.Y.Z` и релиз с `deckdrop.py` и `install.sh`; кнопка
«Обновить утилиту» у всех возьмёт его. Коммиты без смены версии релиз не создают, их
проверяет только [`ci.yml`](.github/workflows/ci.yml), на каждой ветке.

**Временно:** в корне лежит собранный [`deckdrop.py`](deckdrop.py). Из него по старому адресу
обновляются копии 0.3.23 и старше, после чего сами переключаются на релизы. Когда таких
копий не останется, файл можно удалить. Пока он есть, CI требует, чтобы он совпадал
со сборкой: `python tools/build.py -o deckdrop.py`.

[`install.sh`](install.sh) — установщик для дека, принимает ссылку на `deckdrop.py`
первым аргументом или в `DECKDROP_SRC`.
